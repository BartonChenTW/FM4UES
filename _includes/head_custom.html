{%- comment -%} Apply the reader's saved light/dark preference before the page paints. just-the-docs' color scheme is a static build-time choice (_config.yml's color_scheme) rendered as a single pointing at assets/css/just-the-docs-.css. jtd.setTheme(name) (used by the toggle button in nav_footer_custom.html) works by rewriting that link's href at runtime -- there is no data-theme attribute or CSS variable switch involved, confirmed against the theme's own source (jtd.setTheme selects the first [rel="stylesheet"] link and points its href at "assets/css/just-the-docs-" + theme + ".css"). This script does the same href swap, but as early as this include runs (near the end of , after the theme's own stylesheet links are already in the DOM -- confirmed against the theme's head.html) rather than waiting for the toggle button's click handler, so a returning visitor's saved preference applies before first paint instead of after a visible flash of the site's default light scheme. It can't be perfectly flicker-free without restructuring the theme's own head.html, which isn't worth forking just for this. {%- endcomment -%} {%- comment -%} Open external links in a new tab, leaving internal navigation alone. Why a script rather than editing every link: the book's citations are Markdown footnotes written as [Title](https://doi.org/...), and Markdown has no syntax for target="_blank". Adding raw to each of the ~90 external links would make the source far less readable and be easy to forget on new citations. This handles every external link automatically, including ones added later. Internal links (chapter pages, anchors, the glossary) deliberately stay in the same tab -- opening a new tab for each step of normal navigation through the book would litter the reader's tab bar. rel="noopener noreferrer" is set alongside target="_blank": without noopener, the opened page gets a reference to this one via window.opener and can navigate it elsewhere (the "tabnabbing" issue). Modern browsers imply noopener for target="_blank", but older ones do not, and it costs nothing to be explicit. {%- endcomment -%} {% include footnote-tooltip.html %} {% include diagram-zoom.html %}
